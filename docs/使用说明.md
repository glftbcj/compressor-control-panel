# 冷却控制台使用说明

## 下载与首次打开

在 [GitHub Release](https://github.com/glftbcj/compressor-control-panel/releases/latest) 下载 **hvacr.exe**。只需保留这一个文件并双击；无需 .NET SDK、Node.js、旁置 DLL、settings.json 或启动脚本。界面需要本机 Microsoft Edge WebView2 Runtime，缺少时会显示提示。

公开版不含个人 MQTT 凭据。首次打开填写 MQTT 服务器、账号和密码，点击 **保存并连接**；这里需要 MQTT 连接凭据，不是面板里新增的设备 ID。保存成功后下次直接打开。可选择 **离线预览** 体验界面，或 **暂不连接** 先进入控制台。

已配置过的电脑直接复用本机数据；旧 exe 旁的 settings.json 在缺少用户目录配置时自动迁移。无需重新填写设备 ID 或外观。正常启动默认只读。

## 设备与控制

顶部添加自己的设备 ID，选择要使用的设备。打开软件及连接恢复后立即查询所选设备状态，之后保持实时更新。**通信已连接** 表示 MQTT 连接状态，控制还需要有效设备回读与启用控制模式。

在 **设备控制** 卡片点击 **启用控制** 即可操作，无需二次窗口或重启；可随时 **切回只读**。模式切换本身不发送设备指令，仅本次运行有效。

- **温度**：输入 −20–50℃ 内的目标，可使用小数或 ± 按钮。点击 **应用** 直接发送，无二次确认。
- **水泵**：拖动滑块选择 1–10 挡，点击 **应用** 直接发送，无二次确认。拖动只编辑，不发指令，不允许设为 0。
- **启停**：位于独立折叠区域，保留影响散热的确认项。
- **设备管理**：顶部选择、添加和移除设备。移除只删除面板记录。
- **外观**：右上角选择浅色、暗色或跟随系统，以及主颜色或 #RRGGBB。即时预览并自动保存，点击 **完成** 等待保存成功后关闭；失败会提示并允许重试。
- **退出**：关闭控制台只退出程序，设备继续运行。

正常使用没有单次 1℃ / 一个挡位限制，也没有固定调整间隔。新鲜回读确认后可继续操作；上一条未确认或发送结果不确定时不能继续控制，不会自动重发。

## 设定与回读的区别

发送后立即显示本机目标和等待回读状态，并主动查询；一致回报到达后标明。温度、水泵的编辑值不会被定时刷新覆盖。

本次程序下发的目标会保留，刷新页面或调整另一项仍保留。若云端后来回报不同值，下方显示具体差异，不会悄悄替换目标，也不会自动重发。实际水温和原始回报继续更新。重启后初始设定来自云端，本机目标不代表已验证的实时硬件状态。

水温的「几秒前更新」在同一条回报上只递增，收到新水温回报重新计时；迟到的旧响应不能倒退计数。发送和界面更新没有额外五秒等待；真实回读速度仍取决于云端与设备，未收到回报时显示等待状态。

## 数据位置

连接信息 settings.json、设备记录 devices.json、外观 appearance.json 和 WebView2 用户数据默认统一保存在 `%APPDATA%\HVACR`。移动 exe、换访问端口或清理浏览器缓存，不影响已保存外观与设备。

优先级：环境变量 > HVACR_SETTINGS 指定文件 > 用户数据目录的 settings.json。缺少用户目录配置时迁移旧 exe 旁文件；本地个人定制包还可从内嵌默认配置初始化。已有文件不会被自动覆盖。指定 HVACR_DATA_DIR 可变更目录。

文件没有加密；不要分享自己的配置、设备记录或内嵌凭据的个人包。公开 Release 附件不含这些私人数据。

## 离线预览和启动参数

```powershell
.\hvacr.exe --simulate
.\hvacr.exe --control
.\hvacr.exe --read-only
```

`--simulate` 不构造 MQTT 客户端，数据独立放在 `%APPDATA%\HVACR\demo`。`--control` 仅改变本次真实启动模式；通常在界面启用控制更方便。`--read-only` 强制本次只读。

## 云端权限与开发验证

厂商共享认证允许第三方绕过本地面板的风险仍存在。真正设备隔离需要专属身份、服务器主题 ACL 或固件配合；本机 API 令牌无法完成云端隔离。见 [安全边界](安全边界.md)。

自动开发验证只使用离线模拟器。用户明确授权实机测试时每次最多改变 1℃ / 一个挡位，不实机启停或更改 MQTT 配置。这是开发测试约束，不限制日常使用。见 [验证记录](验证记录.md)。
