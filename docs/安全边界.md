# 安全边界

原 C# 实现与工作区中的 Android 反编译代码均使用厂商云端 MQTT 服务和固定共享账号，控制主题为设备 ID/app。原 C# 还允许任意 action 作为 JSON 字段发送，订阅 +/bxkt/#，并在发布后乐观修改遥测。

本次没有探测其他人的设备或厂商管理接口。没有验证厂商当前的服务器 ACL，也没有发现本应用可以调用的可信设备绑定授权流程。

本地改进包括：移除默认明文凭据与真实 ID、默认只读与仅本机监听、局域网访问密钥、跨站与 Host 检查、写入会话检查、精确设备订阅、动作白名单、绝对数值范围、字段有效期、期望基准、去重与回读确认。按用户要求去除固定调整间隔。

只读可在界面内明确启用控制，切换接口同样需要会话令牌与访问密钥（已配置时）。切换不会向设备发送指令，也不改变 MQTT 权限；模式仅在本次运行有效。正常控制没有单次 1℃ / 一个挡位限制，此限制只适用于用户授权的实机开发测试。

配置文件没有加密；拥有文件读取权限的本地用户仍能读取它。

公开 Release 的 exe 不内嵌个人连接凭据或设备 ID，首次连接由用户填写，配置原子保存到本机用户目录。`-PublicRelease` 明确跳过私有配置查找，独立输出公开包；发布前用强制离线入口核对内嵌配置资源不存在。

本地个人桌面包仍可在构建时嵌入自己的连接默认配置，首次运行自动初始化用户目录。私有输入与个人 exe 不提交、不上传。内嵌资源不提供凭据加密或云端隔离，个人包具有与配置文件相同的私密性。桌面版已有用户目录配置优先，兼容迁移旧旁置文件，不会自动覆盖已有数据。

## 客户端无法完成的修复

第三方仍可能用厂商共享凭据直接发布控制主题。面板密码、HTTP 令牌、只读模式、设备 ID 格式及精确订阅不会改变云端 MQTT 权限。

完整修复需要设备专属身份与服务器 topic ACL。可选方案是厂商修复，或设备固件支持更换 Broker 时迁移到自管服务器。不能在不确认固件支持时修改正在运行的设备配置。

凭据可能仍在旧公开 Git 历史和原始资料中，本次删掉源码中的默认密码不会使它失效。撤销共享凭据必须由服务器运营方配合。

## 回读和传输

协议没有应用可验证的设备签名或指令关联 ID。“已回读”表示指令后观察到相关字段的目标值，不证明回报来自可信硬件，也不证明散热长期稳定。

控制采用 QoS 0、不保留消息、断线不重放，避免客户端自动重复控制。超时保留不确定状态，等待新回读。

去重与待确认记录保存在进程内存，重启会重置；其他客户端与多进程不共享这些边界。桌面真实模式采用单实例限制。

实时状态流同样接受 Host、跨站与可选 Bearer 检查。启用控制、调温和调速采用单次点击，数值仍经后端范围、期望值及相关字段有效期检查。压缩机启停保留确认。

本机目标与原始云端遥测分开显示。后续不一致回报不会覆盖本次运行中下发的目标，差异明确列出，不会据此自动重发。目标记录在进程内存，不代表可信的实时硬件状态；真实水温和相关字段的发送基准仍使用原始回报。外观使用本地 appearance.json 持久化，与设备记录同目录，并接受相同 API 访问保护。

厂商 mqtt:// 使用未加密 TCP。程序支持 mqtts:// 并校验证书，但不能假定厂商支持 TLS。局域网 HTTP 的访问密钥也没有传输加密，仅用于可信网络；远程访问需要 HTTPS 或可信隧道。本地 API 令牌不能保护厂商云端。
